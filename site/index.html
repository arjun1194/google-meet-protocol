Four things that surprise everyone

Each of these contradicts what a reasonable engineer would assume, and each one costs a day if you assume it.

01

There is no WebSocket

Signalling is gRPC-Web over ordinary HTTPS POST. Real-time push happens on SCTP data channels inside the media session instead.

02

SDP never crosses the wire

A WebRTC service that never exchanges SDP. Fingerprints, ICE credentials and codecs travel as structured protobuf; the client assembles a description locally.

03

Channels are negotiated over HTTP

Thirteen labels in the CreateMediaSession body — not an SDP m=application section. The server then writes binary onto them with no DCEP open message, ever.

04

Connected ≠ receiving

ICE completes, DTLS completes, and no media arrives until you send a configuration frame on media-director. Nothing errors. Nothing logs.

Ground truth

Annotated wire bytes

Captured frames. Hover or tap any byte to see what it is. Every tag, length prefix and offset is exactly as captured; session identifiers are same-length synthetic placeholders, so anything reading EXAMPLE… is substituted and the rest is verbatim.
